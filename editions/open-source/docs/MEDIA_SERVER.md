# 开源版流媒体指南（ZLMediaKit）

> 本文档专门解决"流媒体相关问题"：端口、RTP、Hook、NAT、对外播放地址。  
> 如果你还没完成系统部署，请先看 [INSTALL_DEPLOY.md](./INSTALL_DEPLOY.md)。

---

## 角色分工

| 组件 | 职责 |
|------|------|
| PyGBSentry 后端 | 业务编排、鉴权、地址生成、SIP 控制 |
| ZLMediaKit | 收流、转协议、分发、回调 Hook |

**简单理解**：后端负责"管控"，ZLM 负责"搬流"。

---

## 部署模式

### 模式 A：同机部署（推荐入门）

- 后端与 ZLM 在同一台机器
- 网络路径最短，配置复杂度最低
- 适合中小型项目

### 模式 B：独立部署（推荐生产扩展）

- ZLM 独立节点（单节点或多节点）
- 适合高并发、跨网段或专门流媒体网络

---

## 关键配置项

| 配置项 | 说明 |
|--------|------|
| `MEDIA_SERVER_HOST` | ZLM 监听地址 |
| `MEDIA_SERVER_HTTP_PORT` | HTTP 端口（默认 8083） |
| `MEDIA_SERVER_RTSP_PORT` | RTSP 端口（默认 554） |
| `MEDIA_SERVER_RTMP_PORT` | RTMP 端口（默认 1935） |
| `MEDIA_SERVER_SECRET` | API 密钥 |
| `MEDIA_SERVER_RTP_PROXY_PORT_RANGE` | RTP 端口范围（如 30000-39000） |
| `MEDIA_SERVER_RTP_STREAM_MODE` | 流模式：UDP / TCP_PASSIVE / TCP_ACTIVE |
| `STREAM_PUBLIC_HOST` | 对外播放地址（公网/IP） |
| `STREAM_PUBLIC_HTTP_PORT` | 对外 HTTP 端口 |
| `MEDIA_SERVER_HOOK_BASE_URL` | Hook 回调地址（ZLM 访问后端） |

## 端口与网络检查清单

上线前至少确认以下 5 项：

| 序号 | 检查项 | 验证方法 |
|------|--------|----------|
| 1 | ZLM 播放协议端口可达 | telnet 端口测试 |
| 2 | RTP 端口段与防火墙一致 | 确认端口范围配置 |
| 3 | Hook 回调可从 ZLM 访问后端 | curl 测试 Hook 接口 |
| 4 | 对外地址配置与真实访问路径一致 | 浏览器测试播放 |
| 5 | NAT 场景优先使用 TCP_PASSIVE | 检查流模式配置 |

---

## NAT 场景建议

| 场景 | 建议 |
|------|------|
| 设备在复杂网络下 | 优先使用 `TCP_PASSIVE` 模式 |
| 不要混淆 | 内网地址和外网访问地址分开配置 |
| 对外播放地址 | 统一通过 `STREAM_PUBLIC_*` 管理 |
| 网关/反代 | 建议明确配置 `MEDIA_SERVER_HOOK_BASE_URL` |

## 常见故障与排查顺序

### 现象 1：页面能打开，但视频黑屏

**先查**：

1. ZLM 端口是否放通
2. RTP 端口段是否放通
3. Hook 回调是否成功

### 现象 2：内网可播，公网不可播

**先查**：

1. `STREAM_PUBLIC_HOST` 是否为外网可达地址
2. 网关端口映射是否正确
3. 防火墙是否遗漏 RTP 端口段

### 现象 3：偶发断流或回放失败

**先查**：

1. ZLM 与后端时间是否同步
2. 网络抖动、丢包与端口冲突
3. 流模式是否与现场网络匹配（UDP/TCP）

## 流媒体端口规划参考

| 端口 | 协议 | 用途 | 必开 |
|------|------|------|------|
| 554 | RTSP | 设备推流/拉流 | 是 |
| 1935 | RTMP | RTMP 推流分发 | 是 |
| 8083 | HTTP | Web 播放（FLV/HLS） | 是 |
| 8443 | HTTPS | HTTPS 播放 | 可选 |
| 30000-39000 | UDP | RTP 收流 | **必须开放 UDP** |
| 9000 | HTTP | ZLM 管理接口 | 内网访问 |

---

## 生产环境建议

1. **先跑通单路**：同一套环境先跑通"单路预览 + 回放 + 报警联动"
2. **再逐步扩展**：验证稳定后再扩展到多设备并发
3. **每次改动后复测**：
   - 预览
   - 回放
   - 轨迹/报警联动中的视频拉流

---

## 最小验收标准

满足以下四项，可判定流媒体链路可用：

| 序号 | 验收项 | 验证方法 |
|------|--------|----------|
| 1 | 实时预览可播放 | 播放一路设备视频流 |
| 2 | 历史回放可播放 | 播放一段历史录像 |
| 3 | 报警联动触发后可拉流 | 触发报警后验证视频 |
| 4 | 跨网访问时播放地址与端口均可达 | 从外部网络测试播放 |
