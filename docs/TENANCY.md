# 多租户使用指南

> PyGBSentry 内置多租户数据隔离,满足"不同账号看到不同设备"（同类平台常见诉求）与
> 代理商/多部门共享一套平台的需求。本文说明租户模型、账号体系与典型部署场景。

## 核心模型

| 对象 | 租户字段 | 说明 |
|:---|:---|:---|
| 用户 `User` | `tenant_id` | 账号归属租户;登录后所有查询自动限定本租户 |
| 设备 `Asset` | `tenant_id` | 设备(摄像头/NVR)归属租户 |
| 通道 `Resource` | `tenant_id` | 通道跟随所属设备 |
| 级联平台 `ParentPlatform` | `tenant_id` | 各租户独立配置自己的上级平台 |
| 录像/告警/报表 | `tenant_id` | 录像记录、报警、流量报表均按租户隔离 |

**隔离规则**:普通用户的所有列表/详情/播放/录像查询自动附加租户条件;`superuser`
(平台超管)可跨租户查看与管理全部数据。数据在数据库层面按列隔离,不同租户互不可见。

## 角色体系

| 角色 | 能力 |
|:---|:---|
| `viewer` | 只读:看自己租户的设备/通道/录像/告警 |
| `operator` | viewer + 播放/云台/订阅等日常操作 |
| `admin` | 本租户全部管理:设备增删、用户管理(本租户)、录像计划等 |
| `owner` | 租户属主:本租户内 admin 全部能力 + 租户级配置(计费/授权等) |
| `superuser` | 平台超管:跨租户管理,由平台运营方掌握 |

## 典型场景

### 场景一:单组织自用(默认)

不配置任何租户——所有账号都在 `default` 租户下,行为与单租户系统完全一致。
**无需任何额外配置。**

### 场景二:一个平台,多个部门/客户

1. 平台超管创建各租户的用户(`superuser` 在用户管理中新建账号并指定租户);
2. 各租户管理员登录后各自添加自己的设备(设备自动归属当前租户);
3. 各租户只能看到/播放/下载自己的设备与录像;告警、报表同样隔离;
4. 级联上级平台、录像计划、插件配置均按租户独立。

### 场景三:代理商模式(配合计费)

租户 + 通道配额(`check_channel_quota`)+ 授权引擎(`entitlement_engine`)组合使用:
按租户限制通道数量与功能授权,超出配额的通道在目录同步时自动跳过并记录。
详见计费与授权相关文档。

## 常见问题

| 现象 | 原因与处理 |
|:---|:---|
| 新增设备后其他账号看不到 | 正常——设备归属添加者所在租户;需要共享请用对应租户的账号添加,或由 superuser 迁移 |
| 提示"设备不存在"但设备确实在线 | 当前账号租户与设备租户不一致;确认登录账号的租户归属 |
| 播放诊断显示"未找到注册记录(或无权限)" | 同上;诊断接口对租户账号只检查本租户设备 |
| 需要跨租户统一运维 | 使用 `superuser` 账号(平台运营方);普通 admin 仅限本租户 |

## 与安全基线的关系

- 租户隔离是**数据可见性**隔离,不替代鉴权:所有接口仍需登录(登录防爆破/锁定/TOTP 均生效);
- 播放 URL 带 HMAC 签名 token(300s TTL),泄漏窗口有限;
- `X-Frame-Options: DENY` 默认禁止 iframe 嵌入管理页,分享/嵌入场景请使用带签名的播放地址方案。
