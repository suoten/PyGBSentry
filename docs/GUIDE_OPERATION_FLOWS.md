# GB/T 28181 协议原理与操作图解

> 本文档通过时序图和流程图，帮助开发者/运维人员深入理解 PyGBSentry 的核心信令流程。
> 适合想了解底层原理或需要深度调试的用户。
> 更新时间：2026-04-13

---

## 1. 信令协议栈

### 1.1 协议层次

```
┌──────────────────────────────────────┐
│         应用层：SIP + SDP              │  ← 信令控制
├──────────────────────────────────────┤
│         传输层：UDP / TCP             │  ← 可靠传输
├──────────────────────────────────────┤
│         网络层：IP                    │
└──────────────────────────────────────┘

┌──────────────────────────────────────┐
│         媒体层：RTP / RTSP           │  ← 视频流传输
├──────────────────────────────────────┤
│         流媒体：ZLMediaKit            │
└──────────────────────────────────────┘
```

GB/T 28181 基于 SIP（RFC 3261）实现设备发现和会话控制，使用 RTP（RFC 3550）传输媒体流。

## 2. 设备注册流程

### 2.1 注册信令流程

```
设备                                    平台（PyGBSentry）                数据库
 │                                          │                            │
 │  ① REGISTER（无认证）                    │                            │
 │ ──────────────────────────────────────> │                            │
 │                                          │ ② 查询设备是否存在         │
 │                                          │ ────────────────────────> │
 │                                          │ <──────────────────────── │
 │ ③ 401 Unauthorized                       │                            │
 │    WWW-Authenticate: nonce=xxx           │                            │
 │ <────────────────────────────────────── │                            │
 │                                          │                            │
 │ ④ REGISTER（含认证摘要）                │                            │
 │    Authorization: username=xxx,         │                            │
 │    response=md5(...)                    │                            │
 │ ──────────────────────────────────────> │                            │
 │                                          │ ⑤ 验证认证信息             │
 │                                          │ ────────────────────────> │
 │                                          │ ✓ 认证通过                 │
 │                                          │ <──────────────────────── │
 │                                          │                            │
 │ ⑥ 200 OK                               │                            │
 │ <────────────────────────────────────── │                            │
 │                                          │                            │
 │  [开始心跳保活]                         │                            │
 │ ⑦ OPTIONS / Keep-Alive                 │                            │
 │ ──────────────────────────────────────> │                            │
 │ ⑧ 200 OK                               │                            │
 │ <────────────────────────────────────── │                            │
 │                                          │                            │
 │  [周而复始，直到设备注销]                 │                            │
```

### 2.2 Digest 认证原理

GB/T 28181 使用 HTTP Digest 认证，核心计算：

```
response = MD5(username:realm:password:method:uri:nonce)

设备发送：REGISTER + Authorization 头（包含 response）
平台验证：使用相同公式计算，对比 response 是否一致
```

### 3.2 SDP 协商内容

INVITE 请求中的 SDP 包含双方协商的媒体参数：

```
v=0                                     ← SDP 版本
o=- 1234567890 1234567890 IN IP4 xxx   ← 会话标识
s=Play                                  ← 会话名称
c=IN IP4 192.168.1.100                 ← 媒体连接地址（重要！）
t=0 0                                   ← 时间（实时为 0 0）
m=video 6000 RTP/AVP 96                ← 视频媒体（端口=6000, RTP/AVP）
a=rtpmap:96 H264/90000                 ← H.264 编码，90000 时钟
a=fmtp:96 profile-level-id=xxxx        ← H.264 详细参数
a=rtcp-fb:96 nackPLI                   ← RTCP 反馈（NACK）
m=audio 6002 RTP/AVP 8                 ← 音频媒体（G.711 A-law）
a=rtpmap:8 PCMA/8000                  ← G.711 A-law 编码
```

## 4. 录像回放流程

录像回放与实时点播类似，区别在于：

| 对比项 | 实时点播 | 录像回放 |
|--------|----------|----------|
| INVITE 请求中的 SDP | `s=Play` | `s=Playback` |
| 时间参数 t= | `t=0 0` | `t=开始时间 结束时间` |
| RTP 时间戳 | 实时递增 | 按录像文件时间戳 |
| 拖动/快进 | 不支持 | 支持 |
| 停止方式 | Bye / 超时 | Bye |

```
用户              PyGBSentry               设备
 │                    │                     │
 │ ① 点击录像回放     │                     │
 │    开始时间: 10:00  │                     │
 │    结束时间: 11:00  │                     │
 │ ──────────────────>│                     │
 │                    │                     │
 │ ② INVITE (SDP)    │                     │
 │    s=Playback      │                     │
 │    t=10:00 11:00   │                     │
 │ ──────────────────>│ ──────────────────>│
 │                    │                     │
 │                    │ <────────────────── │
 │                    │ 200 OK (SDP)        │
 │                    │                     │
 │ ③ ACK             │                     │
 │ ──────────────────>│ ──────────────────>│
 │                    │                     │
 │ ④ RTP 流（按时间戳播放）                  │
 │ <══════════════════════════════════════ │
 │                    │                     │
 │ ⑤ 拖动进度条       │                     │
 │ ──────────────────>│                     │
 │                    │ ⑥ TEARDOWN        │
 │                    │    (停止当前流)     │
 │                    │ ──────────────────>│
 │                    │                     │
 │ ⑦ INVITE (新时间点)│                     │
 │ ──────────────────>│ ──────────────────>│
```

## 5. 云台控制流程

```
用户            PyGBSentry              设备
 │                  │                     │
 │ ① 点击云台方向   │                     │
 │ ───────────────>│                     │
 │                  │                     │
 │ ② INFO (云台指令)│                     │
 │    命令码: PTZCmd │                    │
 │    方向: 左转     │                    │
 │ ────────────────>│ ──────────────────>│
 │                  │                     │
 │ ③ 200 OK        │                     │
 │ <───────────────│ <────────────────── │
 │                  │                     │
 │ ④ 云台开始转动   │                     │
 │ ←────────────── │ ←───────────────── │
 │                  │                     │
 │ ⑤ 松开/停止     │                     │
 │ ───────────────>│                     │
 │                  │                     │
 │ ⑥ INFO (停止指令)│                     │
 │ ────────────────│ ──────────────────>│
```

**PTZ 命令格式（Pelco-D 示例）：**

```
Byte 0: 0xFF        ← 起始码
Byte 1: 地址码       ← 设备地址
Byte 2: 0x00        ← 命令1（方向）
Byte 3: 0x00        ← 命令2（速度）
Byte 4: 0x00        ← 数据1（水平速度）
Byte 5: 0x00        ← 数据2（垂直速度）
Byte 6: 校验码      ← Byte1 XOR Byte2 XOR ... XOR Byte5
Byte 7: 0xFF        ← 停止码
```

## 6. 级联流程

### 6.1 上级平台作为下级注册

```
下级平台 ──────────────────────────────> 上级平台
(PyGBSentry)                              │
   │                                       │
   │ ① REGISTER (作为设备注册)             │
   │ ────────────────────────────────────> │
   │                                       │
   │ ② 401 认证                           │
   │ <──────────────────────────────────── │
   │                                       │
   │ ③ REGISTER (含认证)                   │
   │ ────────────────────────────────────> │
   │                                       │
   │ ④ 200 OK (级联注册成功)               │
   │ <──────────────────────────────────── │
   │                                       │
   │ ⑤ 目录推送 (设备列表)                 │
   │ ────────────────────────────────────> │
   │                                       │
   │ ⑥ 上级点播请求                       │
   │ <──────────────────────────────────── │
   │                                       │
   │ ⑦ 转发 INVITE 给下级设备              │
   │ ──────────────> [IPC]                 │
```

### 6.2 级联点播与本地点播的区别

| 环节 | 本地点播 | 级联点播 |
|------|----------|----------|
| 请求来源 | Web 用户 | 上级平台 |
| INVITE 路由 | 平台 → 设备 | 上级 → 平台 → 设备 |
| 流转发 | ZLM → 用户 | 设备 → 平台 → 上级 |
| 心跳维护 | 平台 → 设备 | 三方均需维护 |

## 8. ZLM 推拉流原理

### 8.1 拉流代理（Pull）

当设备不支持主动发流时，ZLM 可以主动拉取设备的 RTSP 流：

```
设备 (RTSP)          ZLM              用户
(RTSP流)               │                 │
   │                  │                  │
   │  ① 管理员配置拉流地址                │
   │ ─────────────────>│                 │
   │                  │                  │
   │ ② ZLM 主动拉取 RTSP 流               │
   │ <─────────────────                  │
   │                  │                  │
   │ ③ 转码/分发 (FLV/WebRTC)            │
   │                  │                  │
   │                  │ ④ 推送播放地址   │
   │                  │ ────────────────> │
```

### 8.2 推流转发（Push）

RTMP/RTSP 推流到 ZLM 后，转发给国标上级平台：

```
推流端 (RTMP)        ZLM              上级平台
(RTMP流)               │                 │
   │                  │                  │
   │ ① 推流到 ZLM     │                  │
   │ ────────────────>│                  │
   │                  │                  │
   │                  │ ② 转换协议       │
   │                  │    RTMP → RTP    │
   │                  │                  │
   │                  │ ③ 转发 RTP 流   │
   │                  │ ───────────────> │
```

## 9. 流媒体节点负载均衡

```
         用户请求
             │
             ▼
    ┌──────────────┐
    │ PyGBSentry   │
    │ (调度器)      │
    └──────┬───────┘
           │ 查 Redis 获取各节点负载
           │
    ┌──────┴───────┬──────────┐
    ▼              ▼          ▼
 ┌──────┐    ┌──────┐   ┌──────┐
 │ ZLM1 │    │ ZLM2 │   │ ZLM3 │
 │(空闲) │    │(负载) │   │(负载) │
 └──────┘    └──────┘   └──────┘
                ↑
         选择负载最低的节点
         分配新的点播请求
```

Redis 中记录每个 ZLM 节点的：
- 当前连接数
- 流数量
- CPU/内存使用率
- 在线状态
