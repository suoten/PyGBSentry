# 我们把同类项目 456 个公开 issue 读了一遍,然后重写了自己的 GB28181 平台

> 首发:技术社区(掘金 / CSDN / 知乎均可发布)

## 缘起

PyGBSentry 是一个纯 Python 实现的 GB/T 28181-2022 视频监控平台:自研 SIP 协议栈(不依赖任何 SIP 库)、FastAPI 后端、Vue 3 管理端、集成 ZLMediaKit 流媒体,支持设备接入、平台级联、实时预览、录像回放、云台、告警与插件生态。

最近我们做了一件"笨事":把国内最流行的同类开源 GB28181 项目(Java 技术栈)的全部 **456 个公开 issue**(81 个未关闭 + 375 个已关闭)逐条读完、归类、对照我们自己的代码做了两轮系统审计。

结论有点扎心:**93% 的用户诉求不是"更多功能",而是"跑得通、跑得稳"**。

## 用户到底在为什么抓狂

456 个 issue 的分布大致是:

| 痛点 | 占比 | 典型表现 |
|---|---|---|
| 收流超时 / 播放失败 | ~25% | "收流超时"四个字反复出现,根因集中在公网 IP/NAT、多网卡、Docker 网络 |
| 部署 / Docker / 网络 | ~18% | compose 起不来、端口不通、secret 不匹配 |
| 级联(上下级平台) | ~15% | 注册不上、目录不同步、点播 404 |
| 录像 | ~12% | 重启后不录了、文件只有 1 分 29 秒、云端录像打不开 |
| 设备状态不一致 | ~8% | 设备离线通道还在线、全体掉线 |
| 对讲/喊话 | ~6% | 大华能通海康不通,反之亦然 |

还有一个有意思的信号:大量 issue 标题是空的,或者只有一句"BUG"。**用户连自己的问题都描述不出来**——他们缺的不是文档,是一个能直接告诉他"你哪一步配错了"的诊断器。

## 我们做了什么

基于这份分析,我们对 PyGBSentry 做了两轮大修(CHANGELOG 里有完整清单),挑几个有代表性的:

**1. 播放失败自诊断 + 部署体检**
点播失败时,前端直接给出六道关卡的检查结果:设备注册、信令地址、设备可达、流媒体节点(secret 匹配也会指出来)、公网地址是否内网、SSRC 余量——每一项带结论和修复指引。运维中心还有一键"部署体检",九大项全面检查。你在别家遇到的"收流超时"黑盒,在这里是一张体检报告。

**2. 后台任务死接线修复**
我们发现自己也有尴尬事:一次重构把 17 个后台任务模块(录制计划、定时截图、拉流代理自愈等)的启动接线弄丢了,功能"看起来有、从来没跑过"。修复时顺带补上了录制看门狗——周期性向 ZLM 核实真实录制状态,中断自动重启,不再静默丢录像。

**3. 级联目录增量通知**
同类项目被"设备闪断触发全量目录同步风暴"折磨。我们把目录变更改成了防抖聚合的增量 NOTIFY(GB28181 §A.2.5 的 Add/Del/Update/ON/OFF),默认分批发送避免超 MTU,单批失败不再中断整个目录。

**4. 厂商兼容自动化**
对讲/喊话是重灾区(大华要 MESSAGE 先行,海康直连 INVITE)。我们不做成"按厂商手工选",而是平台自动探测每台设备的支持情况:确认了就走标准流程,拒绝的记 24 小时直接 INVITE,超时的短周期重试——开一个开关,混部环境自动适配。

**5. 一些别人踩过的坑我们直接绕开**
SSRC 泄漏导致运行数月后"分配失败"、回放频繁拖动耗尽设备会话数、同录像多客户端互相踢流、心跳地址变化后 INVITE 发旧地址、任意文件读取漏洞……这些在同类项目的 issue 区都能找到受害者,我们的审计清单里逐一排查过。

## 还有这些

- **本地 MP4 虚拟通道**:上传 MP4 就能当一路"直播"播
- **按通道云端录像开关**:三态(跟随全局/强制录/强制不录),告别碎文件
- **分享/嵌入**:一键生成 HMAC 签名的嵌入页,第三方业务系统 iframe 直接用,管理页安全防护不受影响
- **流量账单**:按通道累计流量报表(近 7 天/按日趋势)
- **API 契约**:`/api/v1` 全量端点快照进 CI,删除已发布端点直接构建失败——集成者升级零惊喜
- **多租户**:不同账号看不同设备,租户级数据隔离 + 通道配额
- **公开路线图**:Phase 1-3 全部写明来源与进展

## 技术栈与部署

Python 3.12 + FastAPI + Vue 3 + ZLMediaKit;支持 SQLite(开箱)/ PostgreSQL / MySQL / 达梦;Windows 一键安装包、Docker Compose、便携版 zip、源码部署四条路线。RTP 端口池预分配 + 四路并行 INVITE,首帧 < 500ms。
