# 设备注册失败问题排查

> 本文档专门针对「设备无法注册」这一最常见问题，提供系统化的排查流程与实战案例。
> 更新时间：2026-04-13

---

## 1. 注册流程基础

### 1.1 什么是设备注册

设备注册是 GB/T 28181 的基础机制：
- 设备向平台发送 `REGISTER` 请求，表明身份
- 平台验证设备横号和密码后，接受注册
- 注册成功后，设备与平台之间维持心跳保活
- 任意一方超时未收到心跳，则认为对方离线

### 1.2 注册时序图

```
┌────────┐     ┌──────────────────┐     ┌────────┐
│  设备   │     │   PyGBSentry     │     │   DB   │
│(IPC/NVR)│     │   (SIP Server)   │     │        │
└───┬────┘     └────────┬─────────┘     └───┬────┘
    │                   │                   │
    │  1. REGISTER      │                   │
    │ ─────────────────>│                   │
    │                   │  2. 查询设备ID/密码│
    │                   │ ──────────────────>│
    │                   │                   │
    │                   │  3. 认证结果      │
    │                   │ <──────────────────│
    │                   │                   │
    │  4. 200 OK       │                   │
    │ <──────────────── │                   │
    │                   │                   │
    │  [心跳开始]        │                   │
    │ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ │
    │  5. OPTIONS/心跳   │                   │
    │ ─────────────────>│                   │
    │  6. 200 OK        │                   │
    │ <──────────────── │                   │
    │                   │                   │
```

## 2. 快速排查流程

遇到设备无法注册，按以下顺序检查：

```
设备无法注册
│
├── STEP 1: 网络连通性
│   ├─ telnet 服务器IP 5060 → 不通
│   │   └─ 检查防火墙、云服务器安全组
│   └─ telnet 通
│       ↓
├── STEP 2: SIP 参数核对
│   ├─ 服务器地址正确吗？
│   ├─ 端口是 5060 吗？
│   ├─ 设备横号（20位）正确吗？
│   └─ 密码与平台一致吗？
│       ↓
├── STEP 3: 平台日志查看
│   ├─ 有收到 REGISTER 吗？
│   ├─ 拒绝原因是什么？（401/403/404）
│   └─ 参考下方错误码解析
│       ↓
├── STEP 4: 抓包分析
│   ├─ tcpdump -i any port 5060
│   └─ 确认 REGISTER 是否到达
│       ↓
└── STEP 5: 特殊场景处理
    ├─ NAT 环境
    ├─ 多网卡服务器
    └─ 防火墙/安全组
```

## 3. 错误码详解

### 3.1 401 Unauthorized — 密码错误

**表现：** 设备侧显示注册失败，平台日志出现 `401`。

**原因：** 设备侧填写的认证密码与平台侧记录的不一致。

**排查：**

```bash
# 查看平台日志中的认证失败记录
grep -E "401|Unauthorized|auth" logs/app.log | tail -20
```

**解决：**

1. 登录 PyGBSentry 管理界面 → 设备管理 → 找到对应设备
2. 查看「认证密码」列，记录密码
3. 在设备侧「密码」配置项填写相同密码
4. 重新保存，等待设备重试注册

> 注意：部分设备在修改密码后需要重启才能重试注册。

### 3.2 403 Forbidden — 禁止访问

**表现：** 设备侧显示注册失败，日志出现 `403`。

**可能原因：**
- 设备 IP 未在平台「IP 白名单」中（如果开启了 IP 限制）
- 设备已被管理员禁用
- 服务器同时注册数达到上限

**排查：**

```bash
# 查看禁用/限制相关日志
grep -E "403|Forbidden|disable|block" logs/app.log | tail -20
```

**解决：**
1. 确认设备未被禁用（管理界面设备状态）
2. 如果开启了 IP 限制，将设备 IP 加入白名单
3. 联系管理员确认设备注册上限设置

### 3.3 404 Not Found — 设备不存在

**表现：** 日志出现 `404 Not Found`。

**原因：** 设备的 20 位横号未在平台数据库中登记。

**解决：**

1. 在平台侧「设备管理」中添加设备信息：
   - 设备横号（SIP ID）
   - 设备名称
   - 所属行政区域
   - 认证密码

2. 或者在设备侧修改横号与平台已有记录一致

> 提示：如果使用「自动注册」模式，设备首次注册时会自动创建记录，但需要管理员确认后才生效。

### 3.4 408 Request Timeout — 请求超时

**表现：** 设备侧显示超时，日志无记录或显示超时。

**原因：**
- 设备无法访问服务器（网络不通）
- NAT 环境下端口映射失效
- 心跳周期过长导致路由表老化

**排查：**

```bash
# 在设备网络环境中测试
telnet 服务器IP 5060

# 如果 telnet 成功但仍然超时，检查心跳周期
# 海康设备心跳默认 60s，部分公网环境建议改为 30s
```

## 4. 特殊场景处理

### 4.1 云服务器安全组配置

在阿里云/腾讯云等云平台部署时，需同时在以下两个地方放行：

| 端口 | 协议 | 用途 |
|------|------|------|
| 5060 | UDP + TCP | SIP 信令 |
| 10000-40000 | UDP | RTP 媒体流 |
| 8000 | TCP | Web API（可选） |
| 3000 | TCP | Web 前端（可选） |

**阿里云安全组示例：**

```
入方向规则：
- 5060, UDP, 0.0.0.0/0
- 5060, TCP, 0.0.0.0/0
- 10000/40000, UDP, 0.0.0.0/0
```

### 4.2 多网卡服务器配置

服务器有多个网卡时，SIP 服务默认监听所有 IP，但发流地址可能用了错误的网卡 IP。

**排查：**

```bash
# 查看服务器所有 IP
ip addr
# 或
ipconfig /all   # Windows
```

**在平台侧配置：**

```bash
# backend/.env
# 强制指定 SIP 服务绑定的 IP（多网卡时必填）
SIP_LOCAL_IP=192.168.1.100

# 强制指定流媒体发流的 IP
ZLM_WAN_IP=192.168.1.100
```

### 4.3 NAT 穿透配置

**场景：** 服务器在内网，通过端口映射对外提供服务。

**关键配置：**

```bash
# backend/.env
# SIP 服务监听的本地地址（内网 IP）
SIP_LOCAL_IP=192.168.1.100

# 对外暴露的公网地址
SIP_PUBLIC_IP=你的公网IP

# NAT 映射端口
SIP_PORT=5060
```

设备侧填写的「服务器地址」必须是**公网可访问的地址**。

### 4.4 防火墙规则（Linux）

```bash
# CentOS/RHEL (firewalld)
firewall-cmd --permanent --add-port=5060/udp
firewall-cmd --permanent --add-port=5060/tcp
firewall-cmd --permanent --add-port=10000-40000/udp
firewall-cmd --reload

# Ubuntu/Debian (ufw)
ufw allow 5060/udp
ufw allow 5060/tcp
ufw allow 10000:40000/udp

# iptables (通用)
iptables -A INPUT -p udp --dport 5060 -j ACCEPT
iptables -A INPUT -p tcp --dport 5060 -j ACCEPT
iptables -A INPUT -p udp --dport 10000:40000 -j ACCEPT
```

## 5. 抓包实战

### 5.1 抓取 REGISTER 信令

```bash
# 抓取 SIP REGISTER（UDP 5060）
tcpdump -i any -n port 5060 and udp -c 100 -w /tmp/register.pcap

# 实时查看（不过滤）
tcpdump -i any -n port 5060 -v
```

### 5.2 Wireshark 分析 REGISTER

打开 `.pcap` 文件，过滤查看：

```
# 过滤 REGISTER 请求
sip.Method == "REGISTER"

# 过滤 200 OK 响应
sip.Status-Code == 200

# 过滤 401 响应
sip.Status-Code == 401
```

**正常注册流程应看到：**
1. REGISTER（设备 → 平台）
2. 401 Unauthorized with WWW-Authenticate（平台 → 设备，含随机数 nonce）
3. REGISTER with Authorization（设备 → 平台，含摘要）
4. 200 OK（平台 → 设备，注册成功）

**如果只有步骤 1，没有后续 →** 平台未处理请求，检查平台 SIP 服务状态。

**如果步骤 2 出现后设备不重试 →** 设备不支持 Digest 认证，联系厂商。

## 6. 设备横号编码规则

GB/T 28181 对 20 位设备横号有严格规范：

```
20位设备横号 = 8位行政区域码 + 5位行业编码 + 3位序号 + 4位类型码

示例：34020000001310000001
├─ 34020000   ← 行政区域（省/市/区）
├─ 00         ← 行业编码
├─ 013        ← 序号
├─ 1          ← 保留位
├─ 000        ← 序号扩展
└─ 0001       ← 设备类型（0001=IPC, 0002=NVR）

行政区域编码参照 GB/T 2260-2007
行业编码：
- 00：安全防范
- 01：交通运输
- 02：环境保护
- ...
```

> 注：实际使用中，只要保证唯一性即可，不必完全遵守编码规范。

## 7. 常见问题速查

| 问题 | 原因 | 解决 |
|------|------|------|
| 设备一直离线 | 网络不通 | `telnet IP 5060` 测试 |
| 注册后又立即离线 | 心跳超时 | 缩短心跳周期 |
| 密码正确但 401 | Digest 认证不兼容 | 升级设备固件 |
| 多台设备互相挤掉 | 横号冲突 | 每台设备用不同横号 |
| NVR 在线但无通道 | 通道未推送 | NVR 开启自动上报 |
| 公网设备无法注册 | NAT 穿透未配置 | 配置公网 IP 映射 |

## 8. 管理员操作

在 PyGBSentry 管理后台，可以进行以下操作：

| 操作 | 路径 | 说明 |
|------|------|------|
| 查看注册日志 | 管理 → 审计日志 | 搜索 REGISTER 关键字 |
| 手动添加设备 | 设备管理 → 添加 | 填入设备横号和密码 |
| 批量导入设备 | 设备管理 → 批量导入 | Excel/CSV 导入 |
| 查看在线设备 | 设备管理 → 国标设备 | 状态列显示在线/离线 |
| 重置设备密码 | 设备管理 → 编辑 | 改密码后设备需重注册 |
| 禁用设备 | 设备管理 → 编辑 | 禁用后设备无法注册 |
