# PyGBSentry 路线图

> 本路线图基于对同类项目 wvp-GB28181-pro 456 个公开 issue(81 open + 375 closed,截至 2026-11)的
> 系统性分析制定——93% 的用户诉求不是"更多功能",而是"跑得通、跑得稳、有确定性"。
> 我们按这个优先级排序,并持续公开进展(完成项会移入 CHANGELOG)。

## 用户画像与核心结论

| 画像 | 占比(估) | 他们要什么 |
|---|---|---|
| 集成商/乙方工程师 | ~35% | 级联能注册、对讲能通、部署能交付——**愿为确定性付费** |
| 新手/自学者 | ~30% | 第一次就能跑通,出问题有诊断器而不是文档 |
| 应用开发者 | ~20% | 稳定的 API 契约、签名分享链接、一页嵌入指南 |
| 运维/规模化 | ~15% | 故障自愈、资源不泄漏、多节点、容量与流量统计 |

痛点分布:收流超时/播放失败 ~25%、部署/网络 ~18%、级联 ~15%、录像 ~12%。

## Phase 1 — 让第一次就跑通(进行中)

| 项 | 说明 | 状态 |
|---|---|---|
| 播放失败自诊断向导 | 点播失败时直接给出结论与修复指引(设备未注册 / 信令地址缺失 / 设备不可达 / ZLM 不可达 / 检测到内网地址 / SSRC 余量不足),每项带结论与修法;后端 `POST /api/v1/network-diagnostics/diagnose-play`,前端播放失败界面一键运行 | ✅ 已完成 |
| 兼容性矩阵 | 官方实测的海康/大华/宇视/华为等型号清单,每厂商特殊开关说明(如大华喊话 MESSAGE 前置) | 📋 规划 |
| 公网部署体检 | 运维中心「部署体检」标签页:一键检查 SIP/数据库/Redis/流媒体节点/对外地址/收流配置/安全基线/后台任务/资源,逐项给出结论与修复指引 | ✅ 已完成(`AUTO_DETECT_PUBLIC_IP` / `deploy/setup.sh doctor` 底座已具备) |

## Phase 2 — 集成与兼容(1-2 月)

| 项 | 说明 |
|---|---|
| 对讲旗舰能力 | 厂商模式自动探测(大华 MESSAGE 先行/海康直连 INVITE),"对讲一定能通"作为差异化卖点 |
| 嵌入场景官方化 | "分享/嵌入"一键生成页(签名 URL + 有效期 + 域名白名单),替代全局 X-Frame-Options 一刀切 |
| 多租户权限文档化 | 不同账号看不同设备(#1787 同类诉求)——能力已内置,补使用指南与宣传 |
| API 契约稳定承诺 | OpenAPI 快照测试 + 破坏性变更清单制度,给应用开发者确定性 |

## Phase 3 — 规模化与企业市场(季度级)

| 项 | 说明 |
|---|---|
| GB/T 28181-2022 深化 | MSRC 级联媒体复用、Browse 目录浏览、业务分组/虚拟组织类型码语义(基础信令已支持) |
| 集群与 HA 文档化 | Redis Pub/Sub 多节点已具备,补容量规划与压测报告 |
| 流量账单统计 | 按设备/通道累计流量报表(平台级带宽趋势已有) |
| 视频源扩展 | 本地 MP4 虚拟通道、按通道云端录像开关、告警渠道补全(Telegram/SMS) |
| 付费支持通道 | 集成商交付支持(级联/对讲/部署),按项目收费——商业决策,公开征求意见 |

## 已完成的基础(2026-11)

对照 wvp 456 个 issue 做过两轮系统性对照审计与修复(详见 CHANGELOG [Unreleased]):
部署链路修复、17 个后台任务接线、录制看门狗、级联目录增量通知、SSRC 泄漏治理、
预置位级联转发与多包聚合、大华喊话兼容开关、独立级联鉴权账号、幽灵流对账、
TCP BYE 可靠性等——**同类项目用户踩过的高频坑,已系统性排查并修复**。
